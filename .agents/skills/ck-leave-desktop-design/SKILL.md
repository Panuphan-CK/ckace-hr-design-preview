# CK Leave Desktop Design Workflow

Treat the existing prototype as an accepted design direction to refine, not a blank canvas.

## Read first
AGENTS.md, README.md, flow-function-inventory.md, design-system/ck-leave-desktop/MASTER.md, matching page override, then relevant prototype.js/style.css/page files.

## Classify
- Refine: improve while preserving language
- Extend: add using existing language
- Audit: report only
- Redesign: materially change accepted language; requires explicit owner approval

For Refine/Extend/Audit, do not regenerate global visual identity.

## UUPM
Use $ui-ux-pro-max for focused evidence. Useful examples:
- dense enterprise dashboard hierarchy
- keyboard focus modal
- operations dashboard trend comparison
- professional Thai enterprise typography
- reduced motion dashboard

Do not persist over the accepted CK Leave MASTER.md and never use --force without explicit owner approval.

## Preserve CK Leave
Keep one People Operations command center, top-level module tabs, Thai-first operational copy, navy command surfaces, pale sky canvas, white/glass data surfaces, blue/teal/purple accents, restrained galaxy/aurora motion, and desktop productivity.

## Before large edits
Record current pattern, problem, proposed delta, CK Leave fit, skill evidence, responsive/accessibility risk, and files to change.

## QA
Run $web-design-guidelines and check Thai text growth, 1024/1366/1440/1920 widths, keyboard/focus, reduced motion, color-independent status, overflow/clipping, and global token drift.
